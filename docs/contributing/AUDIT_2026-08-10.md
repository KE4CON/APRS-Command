# APRS Command — Full Multi-Lens Audit (2026-08-10)

Exhaustive audit across seven lenses (reachability/dead-code, APRS parser/spec, transmit safety,
concurrency/resources, transports, security/privacy, tests/build/docs-drift). Baseline at audit time:
**build 0 warnings / 0 errors; 1391 tests pass.** Every finding was verified against source; `file:line`
given so each is checkable. Nothing was changed during the audit.

Status column: ☐ open · ☑ fixed · ⏸ deliberate/won't-fix · ❓ needs decision/verification.

---

## CRITICAL — concurrency (crashes/corruption on real RF operation)

Root cause: only the **APRS-IS** receive path marshals ingestion onto the UI thread
(`Aprs.Desktop/Runtime/LiveDataCoordinator.cs:135-137`). The **KISS-TCP, Serial-KISS, AGWPE, and
managed-modem** coordinators call `AprsIngestionService.IngestReceivedLine` directly from background
receive threads (`KissTcpCoordinator.cs:116`, `SerialKissCoordinator.cs:113`, `AgwpeCoordinator.cs:67`,
`ManagedModemCoordinator.cs:133`), and the shared state they feed has no synchronization. The comment at
`LiveDataCoordinator.cs:41` ("single-threaded") is false for every non-APRS-IS transport.

- ☑ **C1** (fixed 8b0616a) `StationDatabase` has zero synchronization; dictionaries (`StationDatabase.cs:7-13`) written
  from background transport threads while the UI 500 ms timer reads `GetVisibleStations`/`UpdateAgeStates`
  → `InvalidOperationException` / corruption. Triggers on any hardware TNC with live traffic.
- ☑ **C2** (fixed 8b0616a) `RawPacketLogService` has zero synchronization on `entries` (`RawPacketLogService.cs:11`);
  `Add` + `TrimEntries` from background threads while UI enumerates `GetRecentEntries` → crash. Every
  packet. (`TrimEntries` also re-sorts the whole list per packet — O(n log n).)
- ☑ **C3** (fixed, this batch) `RfDiagnosticsViewModel` bound `ObservableCollection`s mutated off the UI thread —
  `App.axaml.cs:104-111` routes TcpKiss/Direwolf `PacketParsed` into `AcceptPacket` without
  `Dispatcher.UIThread.Post` (contrast the marshaled Weather/Telemetry/NetControl handlers at
  `:315/332/345`) → crash on RF setups.
- ☑ **C4** (fixed, this batch) `SqliteStationDatabase` runs concurrent writes on one non-thread-safe `SqliteConnection`
  (`SqliteStationDatabase.cs:42-55`, `:18,33`); overlapping persists throw and are swallowed by
  `catch {}` (`:204`) → silent write loss; dispose-during-use race (`:96-100`).

**One fix closes C1–C3 (+H2 below): marshal ingestion to the UI thread inside the four non-APRS-IS
coordinators (mirror `LiveDataCoordinator`), or add real locking in `StationDatabase` +
`RawPacketLogService`.** C4 needs its own serialization (a write queue / connection lock).

## HIGH

- ☐ **Reachability — 5 genuinely orphaned features** (built + live-wired, no UI entry point). Prior
  reviews found 3; this pass confirmed them and found 2 more. ❓ hold vs wire (decision):
  - **Geofence editor** (`GeofenceEditorView`) — CRITICAL sub-item: the geofence engine runs live
    (`App.axaml.cs:261`, fires alerts) but its only config UI is never shown → **you can't create a
    geofence at all**.
  - **Simulation** (`SimulationView`), **Training** (`TrainingModeView`) — VMs live-wired
    (`DesktopRuntime.cs:264,265,293`), views never hosted; manual ch.26 tells users to open tabs that no
    longer exist.
  - **Direwolf Profile** (`DirewolfProfileView`), **File Hooks** (`FileHooksView`) — VMs live
    (`DesktopRuntime.cs:255,266`), views never referenced.
  - ⏸ **RepeaterBook** (`RepeaterDirectoryWindow`) and **Winlink** (`WinlinkGatewaysWindow`) are also
    unreachable but **deliberately** (decisions-log P4/P5, pending permissions). Not bugs; manual ch.32/33
    already held.
  - Dead: `enum MainFeaturePanel` (`MainFeaturePanel.cs:3`, only self-referenced — vestige of a removed
    feature-area tab strip).
- ☑ **Security H1 (fixed) — Stored/reflected XSS in the Mobile Companion web page.** Received APRS fields
  (comment/callsign/message body/roster) are injected into the served phone page via `innerHTML`/template
  literals with no escaping (`MobileCompanionServer.cs:479,486,503-509,528-536,548-554`). A station
  beaconing `<img src=x onerror=…>` runs JS in the operator's phone browser; the in-page session token
  (`:419`) can be exfiltrated. Server binds all interfaces (`:101`). Fix: HTML-escape all packet-derived
  strings + add a CSP.
- ☑ **Security H2 (fixed) — WebSocket auth fail-open (latent).** `WebSocketEventStreamService.cs:118-129`:
  `RequireToken=true` + empty token ⇒ guard short-circuits ⇒ any non-empty token accepted; non-constant-
  time compare. Mirror the REST fail-closed + `FixedTimeEquals` (`LocalRestApiService.cs:281-298`). Not
  yet wired to a socket (v2), so latent.
- ☑ **Transport H1 (fixed) — AGWPE frame decoder desyncs on normal split TCP reads.** `AgwpeFrameCodec.cs:103,148`
  treats a not-yet-arrived payload (`length > bytes.Count`) as corrupt → emits a header-only bogus frame,
  orphaned payload bytes reinterpreted as the next header → cascading packet loss. Fix: incomplete test
  = `offset+HeaderLength+length > bytes.Count → wait`; bound oversize by a max-frame constant.
- ◐ **Transport H2 / Safety H (thread-safety FIXED; transmit-gate still pending) — AGWPE client skipped the hardening passes.** `AgwpeClient` is not
  thread-safe (unsynchronized `stream`/`State`/`LastError`, send-during-reconnect race —
  `AgwpeClient.cs:19,45,47,91,159,184,197`) **and** its transmit primitive `SendPacketAsync` (`:133`)
  bypasses the global inhibit gate (would ignore exercise mode). Not live for TX today (AGWPE is
  receive-only), but must be gated + synchronized before any AGWPE TX ships. *(Found independently by the
  transport and transmit-safety auditors.)*
- ☑ **Concurrency H1 (fixed)** — Unbounded `Channel` memory leak on the main RX path. Every transport client
  publishes to two unbounded channels but coordinators drain only one, so the other grows for the whole
  session (`AprsIsClient.receivedPackets` never drained; KISS/AGWPE frames-vs-packets mismatch). Fix: all 7
  `Channel.CreateUnbounded` sites in Aprs.Transport (AgwpeClient/AprsIsClient/SerialKissClient/TcpKissClient)
  now `CreateBounded(4096, FullMode = DropOldest)` — an undrained channel caps at 4096 items instead of
  growing without bound; a drained channel drops oldest only under sustained backlog.
- ☑ **Parser H1 (fixed)** — Negative temperatures break the weather parser. `AprsWeatherParser.cs:390` reads 4
  chars when temp starts `-`, but APRS temp is always 3 chars; our own formatter emits 3
  (`AprsWeatherFormatter.cs:189`). Every sub-freezing report loses temp + humidity + pressure into the
  comment; round-trip broken. Untested (fixtures use 72 °F).
- ☑ **Parser H2 (fixed)** — Snow field-code mismatch. Formatter emits lowercase `s` for snow
  (`AprsWeatherFormatter.cs:89-92`); parser reads `s` as wind speed and expects uppercase `S` for snow
  (`AprsWeatherParser.cs:203-214,306-316`). Our snow packets round-trip wrong; incoming spec-snow
  misdecoded. Fix the internal mismatch (align to spec: `s` disambiguated by position).
- ☐ **Docs H — In-app Keyboard Shortcuts window lists 7 keys that do nothing** (`Ctrl+M/W/R/S` + map
  `+/=,-,Home`) — none bound (`KeyboardShortcutsWindow.axaml` vs `MainWindow.axaml:13-18`). The printed
  manual (ch.36) is correct. **Decision already made: wire the missing shortcuts**, then add them to ch.36.

## MEDIUM

- ☑ **Safety M/H (fixed) — RF inhibit gate pushed into the primitives.** `TcpKissClient`, `SerialKissClient`
  and `AgwpeClient` now each expose an `InhibitGate` and check it at the very top of their send methods
  (before any other validation), so a caller that bypasses `KissRfBeaconTransmitClient` still cannot key up
  during exercise mode — no bytes reach the wire. The gate is wired onto every client the KISS/AGWPE/managed-
  modem coordinators create (from `TransmitSafetyAuthority`). Regression test:
  `TcpKissClient_WhenInhibited_BlocksTransmitAndWritesNoBytes` (asserts failure + zero bytes written).
- ☑ **Safety M (fixed) — Message send/retry duplicate-send race.** `SendMessageAsync` (UI) and
  `ProcessRetriesAsync` (10 s tick) both transmitted + updated the same record with no mutual exclusion.
  `AprsMessageRetryEngine` now holds a per-message `SemaphoreSlim` around both paths and re-reads the
  record under the lock in the retry loop, so an ACK arriving between selection and send cancels the retry
  instead of double-transmitting. Regression test: `SendAndRetry_ForSameMessage_NeverTransmitConcurrently`.
- ☑ **Concurrency H2 (fixed) — `StationTrailService` raced off-thread + unbounded key growth.** The
  service now guards all access with its own `sync` lock (no longer relies on every caller being on the UI
  thread), `GetTrails` returns deep copies, and `MaxStations` (default 500) evicts the least-recently-heard
  station so a busy feed can't grow the dictionary without bound. Regression tests in
  `StationTrailServiceTests` (cap eviction + concurrent record/read).
- ☑ **Concurrency M1/M2 (fixed) — `BeaconService`.** `ApplySettings` now disconnects *and* disposes the
  replaced APRS-IS client off-thread (`DisposeReplacedClientAsync`), releasing its CTS/receive-task/socket;
  the tick loop now logs faults via an injected `ILogService` instead of swallowing them silently.
- ☑ **Concurrency M3/M4 (fixed) — leaks.** `OfflineMapDownloadViewModel` moves the progress timer to a
  `finally` (stop + dispose) so a throw/cancel can't leak a forever-firing timer; `ScheduledMessagesViewModel`
  now implements `IDisposable` with named handlers and unsubscribes (DI disposes the singleton on shutdown).
- ☑ **Transport M1 (fixed) — APRS-IS drops packets bundled after `logresp` on reconnect.** The
  pending-data drain ran once before the receive loop, never after a reconnect, so packets pipelined
  behind the reconnect's logresp were dropped. Drain now runs at the top of every loop iteration
  (`AprsIsClient.DrainPendingData`). Regression test: `TransportReconnectRegressionTests`.
- ☑ **Transport M2 (fixed) — stale partial-frame bytes carried across reconnect** (KISS + AGWPE; `pending`
  now `Clear()`ed in the reconnect branch of AGWPE, TcpKiss, and SerialKiss receive loops).
- ☑ **Transport M3 (fixed) — unbounded `pending` buffer growth** on garbage/no-FEND input (KISS). Both KISS
  clients now cap reassembly at `MaxPendingBytes` (1 MiB) and drop the buffer when no frame delimiter is
  found — a real KISS frame is far smaller.
- ☑ **Transport M4 (fixed) — AGWPE reconnect leaks the old stream/socket** (`AgwpeClient.cs:197`).
- ☑ **Transport M5 (fixed) — Reconnecting state bypassed the duplicate-connection guard** (all 4 clients).
  Each `ConnectAsync` guard now also no-ops when `Reconnecting`, so a Connect during auto-reconnect can't
  start a second receive loop. (Faulted correctly still allows a fresh connect — that loop has exited.)
- ☑ **Transport M6 (fixed) — serial read timeout faulted a healthy idle link.** `SystemSerialPortConnection.
  ReadAsync` now catches `TimeoutException` and keeps waiting instead of returning 0 (which the KISS loop
  reads as a close) or letting it fault the link.
- ⏸ **Parser M1 — Area-object offset scaling: verified CORRECT, no change.** `AprsAreaObjectEncoder`'s
  `offset_degrees = value²/100` matches PROTOCOL.TXT. The `/1500` was a stale earlier draft of the
  programming-guide primer, since corrected (see `docs/architecture/APRS_SPEC_CONFORMANCE_PLAN.md:55-60`,
  which explicitly notes "an earlier draft had ×1500"). False positive.
- ☑ **Parser M2 (fixed) — MDHM (8-digit) timestamp position reports misparsed.** The parser read a fixed
  7-char timestamp and started latitude at offset 8, so an MDHM (`MMDDHHMM`, no designator) position was
  read starting mid-timestamp. It now detects MDHM (8th char is a digit, not a z/h// designator) and shifts
  latitude one byte later. Regression: MDHM row added to `TryParse_ReturnsPositionPacket_ForUncompressedPosition`.
- ☑ **Parser M3 (fixed) — message ack edge cases.** Reply-ack `text{MM}AA` now splits into this message's
  id (MM) and the acknowledgement (AA) instead of storing `MM}AA` as the id. Lowercase "ack…"/"rej…" prose
  (e.g. "acknowledge please") is no longer misclassified as an acknowledgement — the remainder must be a
  plausible 1–5 char alphanumeric message number; a trailing reply-ack `}` is handled. Regression tests:
  `Spec_ReplyAckMessage_SplitsMessageIdAndAcknowledgement`, `Spec_LowercaseAckProse_IsNotAnAcknowledgement`.
- ☑ **Security M1 (fixed) — Companion Leaflet CDN now has Subresource Integrity.** The `leaflet.css`/
  `leaflet.js` `<link>`/`<script>` tags carry the official 1.9.4 `integrity` (sha256) hashes +
  `crossorigin="anonymous"`, so a tampered unpkg response is rejected by the browser. (The third-party
  connection itself is inherent to a CDN-hosted map; a fully-bundled Leaflet would remove it entirely and
  is a reasonable future hardening.)
- ☐ **Security M3 / Tests — no UI-wiring/reachability tests and no end-to-end transmit-block test.** The
  1391 tests don't cover the Avalonia views; `MobileCompanionServer` has zero tests; the WS fail-open case
  is untested. This is why the orphaned features + concurrency bugs slipped past. Add: a reachability test
  (every menu command resolves), a Deny⇒no-bytes transmit test, companion HTML-escaping tests.
- ☑ **Build M4 (fixed) — analyzers elevated.** `Directory.Build.props` now sets `EnableNETAnalyzers`,
  `AnalysisLevel=latest-recommended`, `EnforceCodeStyleInBuild`, and a curated root `.editorconfig` silences
  pure-style/naming/micro-opt noise (CA1707 test-name underscores dominated at ~1940) while keeping genuine
  correctness rules as warnings. This surfaced a real bug — `NwsAlertService` ignored `DateTimeOffset.TryParse`
  and would stamp a malformed alert `effective` time as `MinValue` instead of `UtcNow` (CA1806, now fixed).
  A surfaced backlog remains visible in CI (non-blocking): CA1001 ×12 (Avalonia VMs/Views owning disposables
  the framework doesn't dispose), CA2208 ×10 (argument-exception construction), CA1852 ×2 (seal internal
  types). Left as warnings deliberately, per M4's intent to surface rather than bury.
- ☐ **Docs M — Menu Reference (ch.37) omits the Tools "Exercise Traffic Marking" item + its title-bar
  badge; lists `Ctrl+?` where the binding is `Ctrl+/`.** Manual fixes.

Transmit-safety architecture (no *live* ungated path; exercise-mode inhibit, RF-off-by-default,

## Convergent themes
1. **AGWPE was skipped in both hardening passes** (thread-safety + transmit-gate) — found independently by
   two auditors.
2. **Non-APRS-IS transports never marshal to the UI thread** — the root of all four concurrency Criticals.
3. **No test asserts feature reachability or that "deny" blocks transmit** — why orphaned features and the
   concurrency bugs were invisible to CI.

## Fix order (proposed)
1. Concurrency C1–C4 (+H2, trails) — the real-world crash/corruption tier.
2. Security H1 (companion XSS) + H2 (WS fail-closed).
3. Transport H1 (AGWPE decoder) + AGWPE thread-safety/gate; then transport M-tier.
4. Parser H1/H2 (weather) + verify M1 scaling.
5. Reachability (per decision) + docs fixes + wire shortcuts.
6. Build hygiene (enable analyzers) + the missing tests (reachability, transmit-block, companion escaping).

Each fix gets a regression test; the suite stays green.
